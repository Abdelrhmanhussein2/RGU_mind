# ReguMind — Codebase Overview

## What is ReguMind?

ReguMind is an AI-powered academic regulation assistant. Universities upload their regulation documents; students ask questions about those documents and receive accurate, source-cited answers generated by a RAG (Retrieval-Augmented Generation) backend.

There are two user types:
- **Students** — sign in and use a chat interface to query regulations.
- **University Admins** — sign in and use a dashboard to upload / manage regulation documents.

## Page-by-Page Breakdown

### Landing (`/`)
- Two clickable cards: "I am a Student" → `/student/signin`, "I am a University" → `/university/signin`.
- No auth guard; always accessible.

### StudentSignIn / UniversitySignIn
- Email + password form.
- "Remember me" checkbox (state only, not persisted).
- "Forgot password?" links to the respective forgot-password page.
- On submit: navigates directly to `/student/chat` or `/university` (no real auth).

### StudentRegister / UniversityRegister
- Student collects: full name, university, email, password, confirm password.
- University collects: university name, official email, university code, dean name, governorate, password, confirm password.
- Both validate that passwords match before navigating.
- `PasswordStrengthIndicator` renders live feedback below the password field.

### StudentForgotPassword / UniversityForgotPassword
- Single email field.
- On submit: simulates a 1.5 s API call, then navigates to the OTP page, passing `email` via `location.state`.

### StudentOtpVerification / UniversityOtpVerification
- Reads `email` from `location.state` (falls back to `"your email"`).
- 6-slot OTP input (`InputOTP` from shadcn/ui).
- "Resend Code" button is disabled for 30 seconds after page load (via `useEffect` + `setTimeout`).
- On submit: simulates 1.5 s verification, then navigates to the reset-password page.

### StudentResetPassword / UniversityResetPassword
- Two password fields with show/hide toggle and `PasswordStrengthIndicator`.
- Submit button is disabled while passwords don't match.
- On success: shows a success state for 2 seconds, then redirects to sign-in.

### StudentChat (`/student/chat`)
- **Sidebar**: ReguMind logo, "New Chat" button, static recent-chat list, and nav links (Home, Profile, Logout).
- **Main area**: empty state with four example-question cards; once a message is sent, a scrollable message list.
- **Input**: resizable textarea. Enter submits (unless Shift is held or a response is loading). Send button is disabled while `isLoading`.
- **AI response**: simulated with a 1.5 s `setTimeout`. Always returns the same hardcoded answer. Includes copy-to-clipboard and collapsible sources panel.
- **`chats` list** is static (no new-chat creation logic yet).

### UniversityDashboard (`/university`)
- **Sidebar**: three tabs — Upload, Documents, Settings.
- **Upload tab**: drag-and-drop zone + file picker (PDF/DOCX, multiple). On file selection, simulates upload with a progress bar (0 → 100 in 200 ms steps of 10). All selected files are added to the documents list as "processing" on completion.
- **Documents tab**: lists uploaded documents with "Completed" / "Processing" status badges.
- **Settings tab**: university name and contact email fields (uncontrolled, not persisted).

## Shared Components

### `AuthLayout`
Wraps all auth pages in a two-column layout:
- **Left panel** (hidden on mobile): gradient background (`indigo` for student, `purple` for university), decorative image, branding, and three feature bullet points that change based on `variant`.
- **Right panel**: white form area, mobile logo, `{children}`.

### `PasswordStrengthIndicator`
Scores a password 1–4 on: length ≥ 8, length ≥ 12, mixed case, digits, special characters. Renders four colored bar segments and a text label (Weak / Fair / Good / Strong). Returns `null` when the field is empty.

### `ImageWithFallback`
Wrapper around `<img>` that catches `onError` and replaces the image with an inline SVG placeholder.

|---|---|---|---|
| 1 | `StudentOtpVerification.tsx` | `useState` used instead of `useEffect` for the 30s resend timer — timer was created as a side effect inside the state initializer, and the cleanup function was never called (memory leak on unmount). | Changed to `useEffect(() => { … }, [])`. |

## Phase 2 — Services Layer + Auth State + Protected Routes

### New Files

```text
src/
├── services/
│   ├── api.ts              Axios instance — baseURL from VITE_API_BASE_URL, Bearer token interceptor, 401 → redirect to /
│   ├── authService.ts      Auth functions (login, register, forgotPassword, verifyOtp, resetPassword, logout, getMe)
│   ├── chatService.ts      Chat functions (sendMessage, getChatHistory, deleteChatHistory)
│   └── documentService.ts  Document functions (uploadDocuments, getDocuments, deleteDocument)
├── store/
│   └── authStore.tsx       AuthContext + useReducer — LOGIN/LOGOUT actions, localStorage persistence, useAuth() hook
└── app/
    └── components/
        └── auth/
            └── ProtectedRoute.tsx  Redirects to / if not authenticated or wrong role
```

### Auth Store (`src/store/authStore.tsx`)

State shape:

```ts
{ user: AuthUser | null, token: string | null, role: "student"|"university"|null, isAuthenticated: boolean }
```

- `buildInitialState()` reads `token` + `user` from `localStorage` on page load — session survives refresh.
- `LOGIN` action persists both to `localStorage`; `LOGOUT` clears them.
- Wrapped at the root in `main.tsx` with `<AuthProvider>`.
- `useAuth()` returns `{ state, login, logout }`.

### Protected Routes

`/student/chat` requires `role === "student"`.
`/university` requires `role === "university"`.

Unauthenticated or wrong-role access redirects to `/` via `<ProtectedRoute>`.

The router uses `createElement(ProtectedRoute, { requiredRole }, createElement(Page))` to wrap protected routes without requiring JSX in the `.ts` routes file.

### Service Layer Pattern

Every service function that calls the backend is marked `// 🔌 BACKEND: <method> <path>` with the real API call commented in. To activate a function against the live backend:

1. Remove the mock `return new Promise(…)` block.
2. Uncomment the `api.get/post/delete(…)` line above it.

### Auth Page Changes

All 10 auth pages now:

- Call the matching `authService` function instead of a bare `setTimeout`.
- Show an inline error banner (`error` state) on failure instead of `alert()`.
- Show a loading state on the submit button while the async call is in flight.
- `loginStudent` / `loginUniversity` / `registerStudent` / `registerUniversity` call `login(user, token)` from `useAuth()` to write the session into the store and localStorage.
- `StudentResetPassword` / `UniversityResetPassword` now read `email` from `location.state` (forwarded by the OTP page) so the backend has context for which account to reset.

### Dashboard / Chat Changes

| File | Change |
|---|---|
| `StudentChat` | `getChatHistory()` called in `useEffect` to populate sidebar; `sendMessage()` called in `handleSendMessage` |
| `UniversityDashboard` | `getDocuments()` called in `useEffect`; `uploadDocuments()` called in `handleFiles` with real async await; progress bar advances to 90% then jumps to 100% on response |
| Both | Logout button now calls `logout()` (clears localStorage) + `authLogout()` (clears store) then navigates to `/` |
